    Driven by spec Section 4.2–4.3. The `LinuxBackend` exports `name: "linux"` and supports three distro families internally — `debian`, `rhel`, `unknown` — selected by parsing `/etc/os-release` via the injected `readOsRelease` runner.

    Distro detection (`detectDistroFamily(osReleaseText: string | null): "debian" | "rhel" | "unknown"`):
    - Parse `ID=...` and `ID_LIKE="..."` lines (handle quoted + unquoted forms).
    - Build a candidate set = `{ID}` ∪ space-separated tokens of `ID_LIKE`.
    - If any candidate ∈ `{debian, ubuntu, linuxmint, pop, elementary, kali, parrot, raspbian, alpine}` → `debian`.
    - Else if any candidate ∈ `{fedora, rhel, centos, rocky, almalinux, amzn, ol}` → `rhel`.
    - Else (Arch, Manjaro, EndeavourOS, NixOS, Gentoo, Void, anything else, AND when `osReleaseText` is null) → `unknown`.

    `installCa(caPath, opts)`:
    - `debian`: copy CA to `/usr/local/share/ca-certificates/synapse.crt` via `runCp(["sudo", "cp", caPath, "/usr/local/share/ca-certificates/synapse.crt"])` THEN `runSudo(["update-ca-certificates"])`. Return `{ installed: true, ... }` on both succeeding (exit 0).
    - `rhel`: same shape, copy to `/etc/pki/ca-trust/source/anchors/synapse.pem` then `runSudo(["update-ca-trust", "extract"])`.
    - If `runSudo` (or the cp step) returns non-zero exit: return `{ installed: false, requiresSudo: true, manualCommand: <the failed command joined with spaces, e.g. "sudo update-ca-certificates"> }`. Do NOT throw. Soft-fail per spec Section 4.3.
    - `unknown`: do NOT invoke sudo or cp. Return `{ installed: false, skippedReason: "unsupported distro <id> — see manual install for your trust store", manualInstallInstructions: <platform-tagged block> }`. For the Arch case specifically, the `buildManualInstructions` output names the Arch trust path (`/etc/ca-certificates/trust-source/anchors/`) and `sudo trust extract-compat`. For other unknowns, a generic block is fine.

    `uninstallCa(caPath, opts)`:
    - `debian`: `runSudo(["rm", "-f", "/usr/local/share/ca-certificates/synapse.crt"])` then `runSudo(["update-ca-certificates"])`. Return `{ removed: true }` if both exit 0; otherwise `{ removed: false }`. (Per project memory "no external users yet — clean slate over backwards compat", we don't need to detect-then-remove; `rm -f` is idempotent.)
    - `rhel`: same shape against `/etc/pki/ca-trust/source/anchors/synapse.pem` + `update-ca-trust extract`.
    - `unknown`: soft-skip with `skippedReason`.

    `checkInstall(caPath, opts)`:
    - `debian`: existence check on `/etc/ssl/certs/synapse.pem` (the symlink update-ca-certificates creates) OR a grep for the CA's PEM body in `/etc/ssl/certs/ca-certificates.crt`. Pick ONE — the symlink-existence check is simpler and the spec leaves implementation choice open. Use `runCp(["test", "-f", "/etc/ssl/certs/synapse.pem"])` (or `runCp(["ls", "/etc/ssl/certs/synapse.pem"])` — anything that the test can intercept with the cp runner without us re-spinning a separate runner). Return `{ caExists: existsSync(caPath), inTrustStore: status === 0, fingerprint: null }` (fingerprint is computed by onboarding.ts, not here).
    - `rhel`: check `/etc/pki/ca-trust/source/anchors/synapse.pem` exists.
    - `unknown`: `{ inTrustStore: false }`.

    `buildEnvSnippet(caPath, proxyPort)`: bash/zsh syntax — identical shape to existing macOS output (the spec confirms in §5.3 that mac + linux share this snippet). Single string with `# Synapse proxy ...` header + two `export` lines.

    `buildManualInstructions(caPath, proxyPort)`: distro-family-aware. Debian gets the `sudo cp ... && sudo update-ca-certificates` instructions; RHEL gets the rhel-equivalents; Arch gets Arch-specific paths; generic unknown gets a "consult your distro's documentation" line + the env-snippet block.
