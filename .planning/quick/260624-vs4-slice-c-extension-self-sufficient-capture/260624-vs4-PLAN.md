# Slice C: self-sufficient extension (chrome.identity sign-in + direct-POST + daemon fallback)

Final slice. The extension signs in via `chrome.identity.launchWebAuthFlow` (capture-scoped
token from Slice B), then POSTs captures DIRECTLY to the backend `/api/capture/browser`
(Slice A) — with the existing loopback daemon kept as a fallback. Extension-only changes;
no prod auto-deploy (the extension is loaded/bundled manually).

## Tasks

### Config + typings
1. `src/config.ts` (new) — `API_URL = https://api.synapsesync.app`, `APP_URL = https://synapsesync.app`
   (mirror mcp/src/cli/config.ts — the canonical prod URLs).
2. `src/chrome.d.ts` — add the `identity` namespace (`getRedirectURL`, `launchWebAuthFlow`).

### Auth (PKCE sign-in)
3. `src/auth.ts` (new):
   - `sha256Hex` (crypto.subtle), `randomHex` (crypto.getRandomValues) — PKCE verifier/challenge,
     matching the backend's hex sha256 (`challenge = sha256Hex(verifier)`).
   - `buildAuthUrl(redirectUri, challenge, state)` → `${APP_URL}/cli-auth?challenge&state&scope=capture&redirect_uri`.
   - `parseCallback(redirectUrl, expectedState)` → code, or null on state-mismatch / missing code.
   - `exchangeCode(code, verifier)` → POST `${API_URL}/auth/cli-exchange` `{code, code_verifier}` → `{api_key, email}`.
   - `signIn()` — orchestrates: redirectUri = `chrome.identity.getRedirectURL()`, launchWebAuthFlow(interactive),
     parseCallback, exchangeCode, store `synapseCaptureToken` + `synapseEmail`. `getCaptureToken()` / `signOut()`.

### Direct-POST + daemon fallback (the core behavior change)
4. `src/worker/index.ts`:
   - `postCaptureToBackend(captureToken, host, turns)` — POST `${API_URL}/api/capture/browser`,
     `Authorization: Bearer`, body `{host, messages}`. **Client-side scrub** each content via
     `scrubSecretValues` from `@synapse/shared/redact.js` (defense-in-depth; backend scrubs too).
   - `getConfig()` also reads `synapseCaptureToken`.
   - `flush()` — per host: try backend if captureToken; on miss/fail fall back to daemon if daemonToken;
     else re-buffer. Opt-out only when NEITHER token is set. heartbeat/drift stay daemon-only.

### Manifest + options UI
5. `manifest.json` — add `"identity"` permission; host_permissions += `https://api.synapsesync.app/*`
   + `https://synapsesync.app/*`; update description (direct OR via daemon).
6. `options.html` + `options.ts` — "Sign in to Synapse" button (user gesture → `signIn()`),
   show signed-in email + "Sign out". Keep the daemon token/port fields as the fallback.

## Tests
- `test/auth.test.ts` — sha256Hex known-vector; buildAuthUrl shape (scope=capture, redirect_uri);
  parseCallback (valid code; state-mismatch → null; missing code → null); exchangeCode request shape;
  signIn happy path (stub `chrome.identity.launchWebAuthFlow` + fetch + storage).
- `test/worker-backend.test.ts` — flush prefers the BACKEND (Bearer, api.synapsesync.app) when a
  capture token is set; falls back to the daemon when the backend POST fails; client-side scrub
  redacts `sk-…` before the POST; opt-out when neither token present.

## Decisions / notes
- Backend-first, daemon-fallback (user: "safer option in both" — keep the daemon as a safety net).
- Client-side scrub on the direct path (secret never transits the wire); backend still scrubs.
- heartbeat + drift remain daemon-only (no backend endpoints for them) — not a regression.
- Capture token model = Slice B's single rotate-on-reauth `ext-browser` key.

## Out of scope

(corp Chrome blocks unpacked dev-mode — user validates on a non-corp browser).
