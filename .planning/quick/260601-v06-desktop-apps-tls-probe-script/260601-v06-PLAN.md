# Quick Task 260601-v06: TLS Pre-Probe for Desktop AI Apps

## Why

Task #118 (run the desktop-apps-proxy-smoke checklist for Cursor, Claude Desktop, ChatGPT Desktop) is pending. The manual test takes ~20 min per app, but the most likely outcome for at least Claude Desktop and ChatGPT Desktop is "cert-pinned, proxy MITM not viable" — the checklist's own "What fails look like" section calls this out as the dominant failure mode.

A 2-minute pre-screen can establish "this app is cert-pinned" without launching it, short-circuiting the manual flow for apps that have no chance of passing. The user then only does the manual test for apps where the outcome is genuinely uncertain.

## Signals the script will check (in priority order)

1. **`NSPinnedDomains` in `Info.plist`** — Apple's first-party cert-pinning declaration. If `api.anthropic.com` is listed for Claude Desktop, the verdict is "cert-pinned, high confidence" — Apple's networking stack will refuse our CA's leaf certs at the OS level, no proxy install fixes it.

2. **Bundled CA stores in `Contents/Resources/`** — files matching `cacert*.pem`, `ca-bundle*`, `cacerts*`. Most Electron apps that cert-pin do so by shipping a private CA bundle and pointing their Node TLS stack at it instead of the OS trust store. Presence = "likely cert-pinned, medium confidence" (not 100% because some apps bundle a CA for cross-platform consistency without actually disabling system trust).

3. **`NSAllowsArbitraryLoads: true` in ATS dict** — explicit opt-out of pinning. Verdict: "proxy-friendly, high confidence."

4. **No signals** → "ambiguous, manual test still required."

## Output

Default: human-readable table for terminal use.
`--json`: structured per-app result for automation / piping to Synapse insights.

## Scope

- macOS only for v1 (the three apps are Mac-first; Linux/Windows can land in a follow-on if needed).
- Probes Cursor, Claude Desktop (`Claude.app`), ChatGPT Desktop (`ChatGPT.app`) at `/Applications/` and `~/Applications/`.
- Does NOT unpack `app.asar` — bundled CAs inside the asar are missed. Acceptable: missed signals just produce "ambiguous" verdict which falls back to the manual test.
- Does NOT modify any system state. Read-only probe.

## must_haves

- `scripts/desktop-apps-tls-probe.mjs` exists, executable.
- Runs on macOS without errors even when all three apps are absent (prints "not-installed" for each).
- Returns exit code 0 in all normal cases (this is informational, not a gate).
- Prints platform-not-supported notice on non-darwin and exits 0.
- `docs/manual-tests/desktop-apps-proxy-smoke.md` updated with a "Pre-check" section at the top pointing readers to the script.
- Atomic commit + push.

## Out of scope

- Actually running the manual smoke tests (user still does that)
- Linux/Windows app probing
- Unpacking `app.asar`
- Network-level testing (no TLS handshakes attempted)
