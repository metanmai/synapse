# Summary — 260601-v06

## What shipped

1. **`scripts/desktop-apps-tls-probe.mjs`** (new, ~180 lines, executable) — read-only static probe of installed desktop AI apps. For each of Cursor, Claude Desktop, ChatGPT Desktop:
   - Looks for the `.app` bundle in `/Applications/` and `~/Applications/`
   - Extracts `Info.plist` via `plutil -convert json`
   - Inspects `NSAppTransportSecurity` for `NSPinnedDomains` (Apple's explicit cert-pin) and `NSAllowsArbitraryLoads` (explicit opt-out)
   - Walks `Contents/Resources/` (depth 4) for `cacert*.pem`, `ca-bundle*`, `cacerts*`, `ca-certificates*.crt`
   - Classifies into one of four verdicts: `cert-pinned` (high conf), `likely-cert-pinned` (medium), `proxy-friendly` (high), `ambiguous` (low)
   - Prints human table by default; `--json` emits structured output

2. **`docs/manual-tests/desktop-apps-proxy-smoke.md`** — added a "Pre-check (2 min — run this first)" section at the top pointing readers at the probe. Workflow: run probe → skip per-app manual section for any app coming back `cert-pinned` / `likely-cert-pinned` → only do the manual launch for `ambiguous` and `proxy-friendly` verdicts.

## Real data from running on this Mac

The probe ran successfully on the current corp Mac and produced actual findings:

| App | Installed | Verdict | Confidence | Why |
|---|---|---|---|---|
| Cursor | ✓ `/Applications/Cursor.app` | **proxy-friendly** | high | `NSAllowsArbitraryLoads=true` |
| Claude Desktop | ✓ `/Applications/Claude.app` | **ambiguous** | low | No static signals (neither pinned domains nor bundled CAs) |
| ChatGPT Desktop | ✗ not installed | — | — | — |

Two interesting findings:

1. **Cursor is proxy-friendly** — the manual smoke test for Cursor should actually pass. This is a strong signal worth surfacing; pre-probe it was an unknown.

2. **Claude Desktop has no Apple-mechanism cert pinning visible.** Common expectation was "definitely cert-pinned"; static signals say "not pinned via NSPinnedDomains, no bundled CA in expected locations." There could still be runtime/code-level pinning the static probe can't see — that's why the verdict is `ambiguous, low confidence` rather than `proxy-friendly`. **But this means the manual test would be genuinely informative**, not a foregone "cert-pinned" finding.

## Decision impact

The cost-benefit on running the manual smoke checklist has shifted:

- **Before probe**: assumption was Cursor maybe-works, Claude Desktop + ChatGPT Desktop both cert-pinned. Expected payoff from manual test: 1/3 wins. Time: ~60 min for all three.
- **After probe**: Cursor high-likely-pass, Claude Desktop real-unknown, ChatGPT Desktop not installed locally. Expected payoff: 1 likely win + 1 real-unknown-to-resolve. Time: ~40 min for the two installed.

The expected ROI is now positive. If/when the user wants to spend 40 min, the manual smoke checklist is worth running for the two installed apps.

## Limitations (documented in script comments)

- **macOS only** — Linux/Windows print a friendly platform-not-supported notice and exit 0. Adding cross-platform support is a follow-on if needed (the desktop apps in question are all primarily Mac-distributed).
- **`app.asar` not unpacked** — Electron apps that bundle their CA inside the packed asar archive are missed by the depth-4 file walk. Verdict for such an app would be `ambiguous`, falling back to the manual test (which is the existing path anyway — no regression).
- **No runtime pinning detection** — an app that pins certs via custom Node TLS code (e.g., `https.Agent` with a fixed `ca:` option) won't show signals in `Info.plist` or as a bundled file. The probe's `ambiguous` verdict catches this case as "unknown; manual test required."

## Tests

The script is heuristic and the only "test" is "does it run and produce useful output without crashing." Both modes (default human + `--json`) verified working on this Mac. Exit code is always 0; no failure path produces an error to CI.
