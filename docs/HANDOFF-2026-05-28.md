## 🔴 Priority 1 — Handoff continuous pre-warm

### Problem

The handoff layer's "where we left off" brief is materialized by a detached `pull-handoff` LLM call. That call is triggered by **`PreCompact`** (fires on `/compact`) and partially by **`SessionEnd`** (fires on `/clear` — flushes events but does NOT pre-warm the handoff per `learning_cf_auto_deploy.md`).

**Neither hook fires on:**
- `ctrl+C` interrupting the claude process
- Killing the terminal window
- OOM / crash
- Laptop sleep + token expiry
- Network drop mid-session
- Hitting context limit without `/compact`

These are the **default** user behaviors. Users do not gracefully `/compact` before closing.

### Evidence

Tanmai (dogfooding user) just `ctrl+C`'d out of an active session and opened a new `claude` instance saying "let's pick up where we left off". The new session received **none** of the prior session's context (Plus/Free gating audit, 5-step fix plan, etc.). The data is intact on the backend — the *curated brief* simply wasn't pre-warmed before the `ctrl+C`.

### Desired behavior

`pull-handoff` should fire **periodically during the live session**, not just on graceful shutdown. The backend's handoff cache stays within minutes of live state. `ctrl+C` then means "you lose the last 5 minutes," not "you lose everything since the cache was last warmed (which could be days)."

### Spec

#### Where the change lives

`mcp/src/capture/daemon.ts` — the background daemon already has a batch-sync loop. Hook the pre-warm into that loop.

The `pull-handoff` CLI command already exists (`mcp/src/cli/run-pull-handoff.ts` — same code path `PreCompact` uses, exposed as a CLI so it can be spawned detached). Re-use it.

#### Trigger logic

```
EVERY batch-sync, if (newEventsCount > 0):
  for each unique project_id touched by the batch:
    if (lastPrewarmAt[project_id] is missing OR Date.now() - lastPrewarmAt[project_id] > PREWARM_MIN_INTERVAL_MS):
      spawn detached: node MCP_DIST pull-handoff --project-id=<id>
      lastPrewarmAt[project_id] = Date.now()
```

`PREWARM_MIN_INTERVAL_MS = 5 * 60 * 1000` (5 minutes) — debounces so a chatty session doesn't fire a pull-handoff per event.

#### Why detached spawn (not in-process)

`pull-handoff` makes an LLM call (~10-30s). The daemon's batch-sync must stay fast (sub-second). Spawning detached preserves both: the warm completes in the background, the daemon returns immediately to its sync loop.

#### Edge cases to handle

- **Process kill mid-spawn**: if the spawned `pull-handoff` outlives the daemon (daemon restart), it should still complete and post to backend. Detached spawn handles this — child process is reparented to launchd/init.
- **Concurrent spawns**: if two `pull-handoff` processes for the same project race, the backend already has UPSERT semantics on the handoff record (last writer wins; both writers produce semantically equivalent content from the same event log). No locking needed.
- **Cost overrun**: in a high-frequency-event scenario (e.g. heavy coding session generating 100s of events/min), the 5-min debounce caps cost. With ~12 pull-handoffs per active hour at ~$0.02 each = ~$0.24/hr per active project — acceptable.
- **Pull-handoff failure**: log to `daemon.log` and continue. Do not retry tight; let the next batch-sync's debounce-check trigger the next attempt naturally.

#### Files to touch

- `mcp/src/capture/daemon.ts` — add `lastPrewarmAt` map + spawn logic. The function `startHandoffLoop` (or whatever wraps the batch-sync) is the integration point.
- `mcp/src/cli/run-pull-handoff.ts` — verify it accepts `--project-id` flag explicitly (if not, add). The PreCompact path may already pass it.

#### Acceptance criteria

1. Existing `npm run test:e2e:all` (9 suites, ~10 min) passes — proves no regressions in the capture/handoff path.
2. New manual test (or extend `e2e-happy-flow.mjs`): start daemon, fire a session-start event, wait 5+ min, verify `GET /api/projects/<id>/brief` returns a non-stale brief WITHOUT having called `PreCompact` or `SessionEnd`. Today, this returns whatever was last computed by a graceful close (could be empty for a fresh project).
3. Add a unit test for the debounce logic in `mcp/test/unit/` — assert that 2 batch-syncs within `PREWARM_MIN_INTERVAL_MS` only fire one pull-handoff.

#### NOT in scope (defer post-launch)

- Backend `GET /brief` computing on-demand if cache is stale (architecturally cleaner but bigger change; keep the cache-first pattern for now).
- Per-project tunable interval.
- UI affordance telling the user when their handoff was last warmed.
